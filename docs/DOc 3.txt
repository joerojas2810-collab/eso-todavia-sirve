# ¡ESO TODAVÍA SIRVE!

GDD 3.0 · Catálogo maestro de objetos, clasificación y componentes

Vamos a definir 30 objetos desmontables para el lanzamiento, cada uno con una estructura concreta, componentes recuperables, materiales, herramientas, dependencias y particularidades.

La idea es que Fable pueda construirlos reutilizando un mismo sistema de desmontaje, pero que desarmar una heladera no se sienta igual que desarmar una motocicleta.

## 1. Sistema de clasificación

Cada objeto tendrá cuatro clasificaciones simultáneas: familia, tamaño, complejidad y estado.

### Familias

| Código | Familia           | Objetos |
| ------ | ----------------- | ------- |
| E      | Electrodomésticos | 01–08   |
| EL     | Electrónica       | 09–13   |
| M      | Motores y equipos | 14–18   |
| V      | Vehículos         | 19–24   |
| I      | Industrial        | 25–28   |
| X      | Especiales        | 29–30   |

### Tamaño y manipulación

| Clase | Descripción          | Transporte                            |
| ----- | -------------------- | ------------------------------------- |
| S     | Pequeño              | Una persona                           |
| M     | Mediano              | Una persona, con penalización si pesa |
| L     | Grande               | Carro o despiece                      |
| XL    | Muy grande           | Grúa o desmontaje estructural         |
| XXL   | Proyecto excepcional | Área dedicada y maquinaria            |

### Complejidad

- D1 — Básica: tornillos, tapas, extracción y clasificación.
- D2 — Intermedia: componentes internos y dependencias.
- D3 — Avanzada: conexiones, cortes y piezas pesadas.
- D4 — Industrial: varias etapas, maquinaria y subensamblajes.
- D5 — Especial: combina sistemas y objetivos narrativos.

### Estados de recepción

Todo objeto puede llegar en estado normal, oxidado, dañado o incompleto. El estado altera fijaciones, calidad y componentes presentes, pero no debe crear contratos imposibles.

## 2. Cómo se construye un objeto desmontable

Cada objeto tendrá un árbol de componentes. Por ejemplo:

### Ejemplo: lavadora

Lavadora

Exterior

Tapa, puerta, panel trasero, controles

Interior

Motor, tambor, bomba, cableado

Piezas completas o materiales

Acero · Cobre · Plástico · Electrónica

Las fijaciones se cuentan como puntos de interacción, no como objetos físicos independientes. Una pieza puede tener cuatro tornillos y seguir siendo un único componente desmontable.

Convención del catálogo: `C` indica componente; `F` indica fijaciones o uniones. Los rendimientos materiales se definen por componente, no se generan automáticamente al golpear cualquier superficie.

## 4.1 Decisiones de clasificación

Al retirar un motor, el jugador puede:

- Venderlo completo: recibe un valor determinado por su calidad.
- Almacenarlo: conserva el motor para un contrato futuro.
- Descomponerlo: obtiene cobre y hierro, pero pierde la posibilidad de vender el motor completo.

El juego debe mostrar una estimación de valor para evitar decisiones completamente a ciegas.

## 4.2 Calidad de componentes

La calidad inicial depende del estado de recepción.

| Estado     | Calidad inicial orientativa |
| ---------- | --------------------------- |
| Normal     | 80–100                      |
| Oxidado    | 55–85                       |
| Dañado     | 25–70                       |
| Incompleto | Variable según pieza        |

Los errores de desmontaje reducen calidad. Las herramientas de precisión ayudan a conservarla.

No se debe permitir recuperar una pieza con calidad superior a la que tenía al recibir el objeto, salvo que exista un sistema explícito de restauración.

| Electrodomésticos | Abrir carcasas, recuperar motores y separar materiales      |
| Electrónica       | Precisión, piezas delicadas y alto valor                    |
| Motores y equipos | Dependencias mecánicas y extracción de módulos              |
| Vehículos         | Muchas tareas paralelas, transporte y piezas pesadas        |
| Industrial        | Maquinaria, desmontaje estructural y operaciones por etapas |
| Especiales        | Misterio, mecanismos únicos y acontecimientos narrativos    |

También debe haber variación dentro de una misma familia.

Por ejemplo, la aspiradora es un contrato corto de recuperación de plástico y motor; la lavadora exige liberar tambor y bomba; la heladera obliga a tratar un módulo sellado; y la secadora introduce conductos y ventilación.

La complejidad crece por nuevas decisiones y operaciones, no simplemente porque cada objeto tenga más fijaciones.

# 8. Especificación de implementación para Fable

Para que estos 30 objetos puedan desarrollarse sin crear 30 sistemas independientes, cada uno debería construirse a partir de un esquema de datos común.

Cada componente necesita un identificador estable y una representación visual clara. El objeto completo debe pasar por estados reconocibles: intacto, parcialmente abierto, parcialmente desmontado y procesado.

### Requisitos para cada objeto

Antes de considerarlo terminado, comprobaría que:

- Puede inspeccionarse y desmontarse por completo.
- Sus componentes desaparecen del ensamblaje y aparecen como piezas recuperables cuando corresponde.
- Las dependencias funcionan.
- Las herramientas requeridas están correctamente identificadas.
- Las piezas se clasifican en los materiales adecuados.
- La calidad y el valor se calculan sin duplicaciones.
- El desmontaje se sincroniza entre clientes.
- Puede guardarse y recuperarse a mitad de un contrato.
- No quedan componentes inaccesibles por errores de posición.
- Tiene al menos un detalle visual, sonoro o mecánico distintivo.

Quedan definidos 30 objetos con sus componentes principales, métodos de extracción, materiales, progresión y particularidades. En los vehículos y proyectos industriales grandes hemos usado grupos de componentes: durante la implementación esos grupos deberán expandirse en piezas individuales, con posiciones, dependencias y estados concretos.

Mi recomendación de producción es crear primero una biblioteca de componentes reutilizables —paneles, fijaciones, motores, cableado, ruedas, controles y módulos— y construir los objetos a partir de ella. Así, cuando Fable termine el sistema de una lavadora, buena parte de esa lógica servirá para la secadora, el lavavajillas y otros equipos.

Eso permite que los 30 objetos sean una meta de contenido razonable, sin convertir cada uno en un proyecto de programación independiente.
